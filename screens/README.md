# 스크린샷 세트: core와 feature (D-121)

v1.0.3 태그 뒤부터 스크린샷은 두 묶음으로 나눈다. 목록은 [scenes.tsv](scenes.tsv)에 있고, `tools/screenshots/select.py`가 이 표를 읽어 이번 라운드에 찍을 장면을 고른다. 촬영·비교 절차는 `docs/SCREENSHOTS.md`에 있다.

- **core**: 매 라운드 찍고, 직전 통과 세트와 픽셀 비교해 바뀐 것만 검토한다. 학생이 실제로 보는 화면 30장이다.
- **feature**: 나머지 장면이다. 장면마다 관련 코드 경로를 짝지어 두고, PR이 그 경로를 건드렸을 때만 찍고 검토한다.
- **원조 2.7.1 비교(`-orig`)**: 원조는 바뀌지 않으므로 v1.0.3 세트(review-shots `2026-09-27-v103/`)의 `-orig` 이미지를 기준 이미지로 쓰고 다시 찍지 않는다. 비교 회로(`tests/circ/demo-datapath.circ`), `lib-mips/`, `vendor/`, 또는 원조 장면(02·03·16·21·23·37)을 찍는 Shots.java 코드가 바뀔 때만 다시 찍는다(`select.py --orig`).
- `-orig` 기준 이미지는 그리기 순서를 고정하기 전에 찍었다. 처음 다시 찍을 때는 겹친 끝점 색 몇 픽셀이 달라질 수 있고, 그 한 번은 바뀐 이미지로 검토한다.
- 릴리스 전에도 같은 규칙이다. 바뀌지 않은 이미지는 직전 판정을 이어 쓴다. 릴리스 직전 전체 세 범위 검토는 하지 않는다.

## feature 장면을 고르는 규칙

- `scenes.tsv`의 `paths` 열: 기준 커밋(기본은 마지막 `v` 태그) 뒤 바뀐 파일이 이 앞부분으로 시작하면 그 장면을 찍는다.
- `global` 줄의 경로(원조 창 `gui/main/`, 테마, `Messages.java`, `run.sh`, 글꼴)가 바뀌면 모든 장면을 찍는다.
- `tools/screenshots/Shots.java`는 파일 전체가 아니라 바뀐 줄이 속한 장면만 고른다. `run()`의 `want(scenes, "NN")` 블록이나 장면 메서드 javadoc 첫머리의 `NN:`로 정한다. 장면 번호가 없는 도우미 메서드(예: `sceneStart`)가 바뀌면 모든 장면을 찍는다.
- 문구 파일(`messages.properties`, `messages_ko.properties`, `names.properties`)은 바뀐 키를 쓰는 소스 파일로 바꿔 `paths`와 맞춘다. 쓰는 곳을 못 찾은 키(동적으로 만든 키)가 있으면 모든 장면을 찍는다.

## 같은 장면은 같은 픽셀

바뀐 것만 검토하려면 코드가 같을 때 이미지가 같아야 한다. 이를 위해 두 가지를 고정한다.

- 원조 엔진은 부품을 `HashSet`에 두고 그 순서대로 그린다. 순서가 객체 해시에 달려 있어, 겹친 끝점의 색과 목록 순서가 JVM을 띄울 때마다 달랐다. 촬영 JVM에만 `-XX:hashCode=2`를 줘 넣은 순서로 고정한다. 앱과 엔진 코드는 바꾸지 않는다.
- 글자 칸의 깜박이는 커서를 멈춘다.
