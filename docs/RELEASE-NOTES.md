# Hallym Circuit Studio 1.0.2

v1.0.1을 Windows 실습실 화면(1024×768)에서 검토하며 나온 창 크기·도구 모음 문제를 고친 패치입니다. 부품과 .circ 형식은 그대로라 v1.0.0·v1.0.1로 저장한 파일을 그대로 엽니다.

## 첫 실행 창이 화면에 맞게 열림

- 처음 실행하면(저장된 창 설정이 없으면) 창이 **주 모니터의 작업 영역에 맞춰 최대화**되어 열립니다. 전에는 640×480으로 왼쪽 위에 열려 도구 모음이 잘리고 캔버스가 작았습니다.
- 창 크기·위치·최대화·칸 폭은 Hallym Circuit Studio의 설정 파일에만 저장합니다. 같은 PC의 원조 Logisim 2.7.1 창 설정은 읽지도 바꾸지도 않습니다. 저장된 창이 화면 밖이거나 화면보다 크면 그 모니터 안으로 맞춥니다. 최소 창 크기는 960×600입니다(작업 영역이 그보다 작으면 그 절반까지).

## 도구 모음이 좁아도 명령이 사라지지 않음

- 창이 좁아 도구 모음이 넘치면 먼저 글자를 숨겨 아이콘만 보이고, 그래도 모자라면 오른쪽 끝 **»** 단추의 메뉴로 보냅니다(도구 모음 순서 그대로). 넓히면 되돌아옵니다. **Run·1 Cycle·Reset·Load .s**는 가장 마지막까지 도구 모음에 남습니다.
- 나란히 보기의 반 폭 창에서도 같은 규칙입니다.

## 좁은 창의 칸 비율

- 캔버스는 창 폭의 절반(최소 480px)을 가집니다. 모자라면 왼쪽 목록과 Attributes 칸이 먼저 줄고, 그래도 모자라면 Attributes 칸이 접힙니다. 직접 정한 칸 폭은 창을 다시 넓히면 되돌아옵니다.

## Registers 탭과 캔버스

- 레지스터 파일을 표시하지 않아 모든 레지스터를 나열할 때, 상태 표시줄이 PC로 판별한 레지스터는 **PC**로 보이고 원래 이름(Register #1)이 곁에 흐리게 붙습니다.
- "레지스터 파일을 표시하지 않아 모든 레지스터를 나열합니다" 안내는 라벨로 $1/R1처럼 이름이 대응되지 않았을 때만 보입니다.
- 라벨 칩·값 칩이 강조된 버스(Active Path·필드 색 띠)에 닿지 않게 선에서 조금 더 떨어져 놓입니다.
- 새 창을 열었을 때 캔버스 아래 Messages 칸이 0 높이로 굳는 일이 없습니다(직접 끌어 닫은 것은 그대로 둡니다).

## 알려진 한계

- 도구는 동작하지 않는 회로만 알린다. 값이 흐르는데 결과가 틀린 회로는 판단하지 않는다.
- Windows 1024×768·100%·150%에서 첫 실행을 확인했다(CI windows-smoke). macOS·Linux는 Java 21 jar로만 제공한다.

# Hallym Circuit Studio 1.0.1

v1.0.0을 써 본 뒤 나온 문제를 고친 패치입니다. 부품과 .circ 형식은 그대로라 v1.0.0으로 저장한 파일을 그대로 열고, 새로 더한 정보(Mark as PC)는 전처럼 `<hcs:ext>` 한 곳에만 들어가 원조 Logisim도 건너뛰고 엽니다.

## 새 파일에서 Hallym MIPS 바로 사용

- 새 파일을 열면 왼쪽 부품 목록에 **Hallym MIPS**가 처음부터 있습니다(흐리게 "(아직 파일에 없음)"). Ctrl+K에서 `instruction memory`, `console`을 쳐도 바로 나옵니다. 더는 Project › Load Library로 설치 폴더의 jar를 찾을 필요가 없습니다.
- MIPS 부품을 처음 놓는 순간 라이브러리가 파일에 들어갑니다(되돌리기 한 번으로 취소). MIPS 부품을 쓰지 않은 파일은 원조 Logisim과 완전히 같게 저장됩니다.
- **원조 Logisim 2.7.1에서 열려면 `hcs-mips.jar`를 .circ 옆에 두세요.** 저장할 때 jar가 없으면 상태 표시줄이 한 번 알리고 **Copy hcs-mips.jar Here** 단추로 복사할 수 있습니다(누르기 전에는 복사하지 않습니다). Create Submission은 전처럼 jar를 함께 넣습니다.

## 처음 여는 학생을 위한 안내

- 빈 회로에는 캔버스 가운데에 할 일 셋(Ctrl+K 검색, 왼쪽 목록에서 끌어 놓기, Help › Examples)이 흐리게 보입니다. 첫 부품을 놓으면 사라집니다.
- **Help › Examples**에서 demo-datapath, console-demo, stack-demo를 읽기 전용으로 엽니다. 저장하면 Save As…로 새 이름을 묻습니다.

## 진단과 사이클 뷰

- E가 생긴 이유를 가려 말합니다: 한 선을 서로 다른 출력이 구동하면 "E(충돌 값)", 정해지지 않은 입력이 게이트를 거친 것이면 "E(오류 값)", 비트 폭이 어긋나면 "E(오류 값, 비트 폭 불일치)". 문구에 `.out` 같은 내부 이름 대신 "AND #3 출력"처럼 읽는 이름을 씁니다.
- 메시지를 누르면 사이클 표 맨 위에 원인 신호와 E가 생긴 자리가 임시 줄로 나타나고 그 사이클 칸이 강조됩니다(파일에는 저장되지 않음).
- 활성 경로는 MUX가 고른 입력까지 오는 가지만 칠합니다(같은 넷의 다른 가지는 칠하지 않음).
- 상태 표시줄 PC를 못 찾는 회로에서는 레지스터를 오른쪽 클릭해 **Mark as PC**로 정할 수 있습니다. 라벨이 pc인 터널이나 Instruction Memory의 Addr도 알아봅니다.

## 편집기

- 같은 이름의 파일 둘을 열면 탭에 구분되는 폴더 이름이 흐리게 붙습니다(`demo-datapath — hw3`). 창 제목과 Window 메뉴도 같습니다.
- Signal Flow의 터널 점프 호가 부품·라벨을 피해 돌아가고, 피할 수 없는 구간만 옅게 그립니다. 연결 없는 출력 포트에는 글자 라벨을 달지 않습니다.
- Tunnels 목록에서 같은 이름이 하나뿐인 터널은 개수 (1)을 흐린 주황으로 보입니다(판정은 아닙니다).

## 알려진 한계

- v1.0.0과 같습니다: 도구는 동작하지 않는 회로만 알리고, 값이 흐르는데 결과가 틀린 회로는 판단하지 않습니다. macOS·Linux는 Java 21 jar로만 제공하며 Verilog는 범위 밖입니다.

# Hallym Circuit Studio 1.0.0

한림대학교 Micro-architecture 실습도구의 첫 공개 릴리스입니다. 수업에서 쓰는 Logisim 2.7.1을 포크해, 학생이 single-cycle MIPS를 설계하다 막히는 곳을 도구가 짚어 줍니다.

## 설치

- **Windows:** `hallym-circuit-studio-1.0.0-windows.zip`을 풀고 `HallymCircuitStudio.exe`를 실행합니다(Java·관리자 권한 불필요). 설치형은 `hallym-circuit-studio-1.0.0-windows.msi`.
- **원조 Logisim 2.7.1을 계속 쓰는 경우(트랙 A):** `hcs-mips-1.0.0-windows.zip`의 `hcs-mips.jar`를 Project › Load Library › JAR Library로 불러옵니다. `hcs-asm.exe`를 같은 폴더에 둡니다.
- **그 밖:** Java 21 이상에서 `java -jar hallym-circuit-studio.jar`.
- 안내: 학생용 `GUIDE-ko.md`, 조교용 `TA-GUIDE-ko.md`.

## 기능 요약

- **MIPS 부품(Hallym MIPS):** Instruction Memory, Data Memory, Stack, Console, Radix Probe. 32비트 주소 그대로, `.s`를 `Load .s`로 올리며 기계어는 QtSpim(Hallym MIPS Simulator)과 같다. .s를 고쳐 저장하면 자동 재로드.
- **진단(Messages):** 동작하지 않는 연결만 알린다 — 정적(연결 안 된 입력, 짝 없는 터널, 폭 불일치, 서브회로 포트, 클럭, 메모리 영역 겹침)과 동적(값이 정해지지 않은 쓰기, E 발생과 출처, 발진, 정렬·영역·스택 문제)을 사이클과 함께. 원인 한 곳, 학생이 붙인 이름, 사실과 위치까지만.
- **사이클 뷰:** 사이클 표, 뒤로 가기, Run Until, 레지스터·메모리·명령어 필드 탭, 활성 경로와 버스 값 표시, Console 탭.
- **편집기:** 파일 탭(분리·나란히 보기·복원), 확대·축소, 라벨 칩과 터널 색, 굵은 버스·비트 수·선 색 범례, 신호 그룹 색, 따라오는 배선과 뜻하지 않은 연결 막기, 영향 경로와 Signal Flow, Duplicate N·Align·Distribute, Auto Appearance와 Port Order, 서브회로 가져오기, 영역 메모, 미니맵, 검색과 명령 팔레트, Undo History, 단축키 설정, 자동 저장과 복구, 제출 zip, PNG·SVG·PDF 내보내기, 첫 실행 튜토리얼, About.

## 원조 Logisim 2.7.1과의 차이

- 시뮬레이션 엔진과 `.circ` 형식은 그대로다. 새 부품을 쓰지 않은 파일은 원조와 바이트 수준으로 같게 저장된다. 이 도구가 더하는 정보(터널 색, 신호 그룹, 영역 메모, 스플리터 팔 이름, 레지스터 파일 표시)는 `<hcs:ext>` 한 곳에 들어가고 원조는 건너뛴다.
- 이름은 원조 영어 그대로이고 설명 문장만 한국어다. Help › Tutorial은 원조 JavaHelp 튜토리얼 대신 창 튜토리얼이다(원조 튜토리얼은 User's Guide 안에 있다).
- Ctrl+0·Ctrl+1은 확대(전체 맞춤·100%)이고 도구 선택은 Ctrl+2~9다.
- 시뮬레이션이 꺼진 동안의 Tick Once·1 Cycle은 무시하고 알린다(원조는 전파 스레드가 공회전한다).

## 알려진 한계

- 도구는 동작하지 않는 회로만 알린다. 값이 흐르는데 결과가 틀린 회로는 판단하지 않는다.
- 원조 Register·플립플롭은 X를 담지 않으므로 "값이 정해지지 않은 쓰기"는 클럭 에지에서 알린다.
- 25% 배율에서는 라벨 칩이 회로에 비해 커서 제 선에서 떨어져 보일 수 있다(지시선 문턱 안).
- 나란히 보기는 창을 반씩 나눌 뿐 배율·스크롤은 각 창의 것이다.
- Windows 100%·150% 배율에서 확인했다. macOS·Linux는 Java 21 jar로만 제공한다.
- Verilog 내보내기는 이 릴리스 범위 밖이다.
