# .hmx 명세

**기준:** Hallym MIPS의 `docs/hmx-format.md`, 태그 `v2.4.0`(커밋 `b3117c701da6a17c22ab6af778ce97e69745ede8`)으로 고정한 원본:
<https://raw.githubusercontent.com/ars2323/hallym-mips-simulator/v2.4.0/docs/hmx-format.md>

명세와 이 도구가 다르면 명세를 따른다(D-138). 이 문서는 명세 본문을 옮기지 않는다. 명세가 정하지 않은 곳에서 이 도구가 고른 것과 불러오기 동작만 적는다. 코드: `lib-mips/src/shared/java/kr/ac/hallym/hcs/mips/image/`(두 트랙 공용, D-125). 명세 골든: `tests/hmx/hallym-mips-v2.4.0/`(README 참고). 손으로 쓴 시험 파일: `tests/hmx/`. 명세 쪽에 바라는 것: [hmx-feedback.md](hmx-feedback.md).

## 받는 파일은 .hmx 하나(D-141)

- **만드는 곳.** Hallym MIPS(2.4.0부터)에서 `.s`를 열고 Ctrl+S로 어셈블한 뒤, 제목 줄 오른쪽 아이콘 묶음의 Export executable image (.hmx) 단추로 내보낸다. 이 도구는 어셈블하지 않는다(hcs-asm과 `vendor/spim`은 지웠다, [hcs-asm.md](hcs-asm.md)).
- **Load Program...** 파일 고르기 창은 "Executable image (*.hmx)" 거르개 하나뿐이다("모든 파일"도 없다). 그래도 `.s`(`.asm`, 대소문자 무관)가 들어오면 이미지 없이 사실과 할 일 한 줄만 알리고 아무것도 바꾸지 않는다: "이 파일은 .s 파일을 가리킵니다. Hallym MIPS에서 Export executable image (.hmx) 단추로 내보낸 파일을 불러오세요." (영어: "This file points to a .s file. Load the file exported with Export executable image (.hmx) in Hallym MIPS.")
- **옛 .circ의 .s 경로.** 메모리 부품의 `source` 속성이 `.s`를 가리키는 옛 파일은 전과 똑같이 열리고, 고치지 않으면 같은 바이트로 저장된다(속성은 읽기만 한다). 트랙 A 우클릭 메뉴는 "Reload 이름.s" 대신 "Load .hmx for 이름.s..."이고, 누르면 위 문장과 속성 값을 보인 뒤 `.s`가 있던 폴더에서 `.hmx` 고르기 창을 연다(같은 이름의 `.hmx`가 있으면 골라 둔다). `.hmx`를 불러오면 `source`가 그 경로로 바뀐다. v2 엔진은 파일을 열 때 같은 문장을 사실 `assemblySource`로 준다(docs/engine-api.md `mips.facts`, 화면은 N-16). 공용 규칙과 문장은 `AssemblySource` 한 곳에 있다.

## 명세대로 하는 것

명세의 "Lines", "Fields", "Sections", "What a reader must do"를 그대로 따른다. 특히:

- 무시하는 줄(빈 줄, `#` 줄)이 아닌 첫 줄이 머리 줄이다. 앞뒤 공백, 탭, CRLF, 16진수 대소문자, 한 줄에 워드·바이트 여럿을 모두 받는다. 앞의 BOM은 건너뛴다.
- 모르는 필드는 읽지 않고 넘긴다(오류가 아니다). 넘긴 필드는 파서 결과(`ignoredFields`)에만 남는다.
- 오류: 1판이 아닌 판, 개수가 맞지 않는 구간(`zero` 칸 포함), `endian`·`entry`·`.text`가 없음, 모르는 구간, 같은 종류의 두 번째 구간, 틀린 숫자(`<addr>`는 `0x` 뒤 16진수 정확히 8자리, `.text` 워드는 8자리, `.data` 바이트는 2자리, 개수는 10진수).
- 구간이 주지 않은 메모리는 0이다. 메모리 부품은 쓴 적 없는 워드를 0으로 내므로 그대로 맞는다.

## 명세가 정하지 않은 곳(이 도구의 선택)

- **같은 필드 두 번.** 오류다(`entry`, `endian`, `source` 등; `reg`는 같은 레지스터, `symbol`은 같은 이름). 어느 값이 맞는지 추측하지 않는다.
- **구간 밖의 워드·바이트 줄.** 첫 구간 앞에 있는 `zero` 줄이나 낱말이 모두 16진수 2·8자리인 줄은 모르는 필드로 넘기지 않고 오류로 알린다(구간 머리가 빠진 파일).
- **첫 구간 뒤의 필드.** 명세는 필드가 구간 뒤에 오지 않는다고 적는다. 구간 안의 알려진 필드 줄은 "첫 구간보다 앞에 있어야 합니다" 오류, 그 밖의 줄은 틀린 워드·바이트 오류다.
- **판.** 1이 아니면(0 포함) 읽지 않고 "이 파일은 실행 이미지 N판입니다" 오류 하나만 낸다.
- **`0X`, `zero 0`, 빈 구간.** `0X` 머리도 받는다. `zero 0`은 칸이 없는 0 구간이다. 개수 0인 구간도 받는다.
- **구간 한계.** `.text`와 `.data`가 한 바이트라도 겹치면, 구간이 `0xffffffff`를 넘으면, 개수가 16M을 넘으면 오류다. `.text` 주소는 4의 배수다(명세).
- **`endian big`.** 읽는다. 메모리 부품은 워드 단위라 바이트 순서를 스스로 정하지 않으므로, `.data` 바이트를 `endian`대로 워드로 묶어 넣는다(명세 6의 "변환"). `little`이면 주소가 낮은 바이트가 워드의 낮은 8비트다(SPIM과 같다).
- **워드 경계가 아닌 `.data`.** 빠진 바이트를 0으로 채워 워드로 묶는다. 바이트 주소는 파일 그대로다.
- **오류 목록.** 오류가 하나라도 있으면 이미지를 만들지 않고 불러오기는 아무 부품도 바꾸지 않는다. 오류는 모두 모아 줄 번호 순으로, 줄이 없는 오류(없는 필드·구간)는 뒤에 둔다(창에는 앞 12개). 구간 안에서 틀린 줄이나 넘친 줄이 있으면 "개수가 모자람"은 따로 알리지 않는다.
- **원본 대조.** `source`를 `.hmx` 폴더 기준 상대 경로로(절대 경로면 그대로) 찾고, 없으면 `.hmx` 옆의 같은 파일 이름을 찾는다. `source`가 없으면 `.hmx`와 같은 이름의 `.s`를 찾는다. 찾은 파일의 SHA-256(파일 바이트 그대로)이 `source-sha256`과 다르면 노란 사실 줄 "원본 파일 lab04.s: 내보낸 뒤 바뀜.", 찾지 못하면 "원본 .s 파일을 찾지 못해 비교하지 않았습니다."를 보인다. 불러오기는 막지 않는다.
- **예외 처리기 없이 어셈블한 이미지.** 기호에 `__start`가 있으면 그렇게 본다. 명세는 처리기 파일의 라벨(`__start` 등)을 기호에 넣지 않고, 처리기를 불러온 채로는 프로그램이 `__start`를 또 정의할 수 없기 때문이다. 워드 모양(시작 코드 9워드)으로는 가리지 않는다(처리기 파일은 설정에서 바꿀 수 있다).

## 불러오기

- `.text`는 파일 주소 그대로(시작 코드 포함, 자르거나 옮기지 않음) 그 구간을 담는 Instruction Memory에, `.data`는 그 구간을 담는 Data Memory에 넣는다. 담는 부품이 없으면 구간과 범위를 말하고 아무것도 넣지 않는다(전부 아니면 전무, D-126).
- **레지스터에는 아무 값도 넣지 않는다.** PC 시작과 레지스터 시작 값은 학생 회로의 몫이다(CLAUDE.md 2.6).
- `reg $sp`가 있으면 그 값 바로 아래 워드를 스택 영역에 담는 부품(데이터와 스택을 함께 맡는 Data Memory, 옛 파일은 Stack, D-140)의 깊이 기준이 된다(SPIM 시작 `$sp` 0x7FFFEFFC 규칙보다 먼저). 스택 내용은 파일에 없으므로 0이다. 코드에서 이 일을 하는 곳은 `ProgramLoader.stackDepthBase` 하나다.
- 기호는 표시(디스어셈블의 `[main]`)에 쓴다.
- **요약(Z-03, `StartFacts`).** 첫 줄은 `entry 0x00400024 (main)`(entry 주소의 기호, 여럿이면 파일 순서, 없으면 괄호 없음, entry가 없으면 `no entry`), 이어서 `reg` 줄마다 한 줄(`reg $sp 0x7fffffe4`, 파일 순서, 표준 이름). 이름·숫자라 두 언어 모두 영어다(D-049).
- **사실 줄**(설명 문장, 언어 설정을 따른다):
  - 예외 처리기 없이 어셈블한 이미지: "예외 처리기 없이 어셈블한 이미지: 시작 코드 없음, 진입점 = 프로그램의 __start."
  - 진입 루틴에 `jr $ra`(워드 `0x03e00008`)가 있으면: "진입 루틴의 jr $ra: 0x0040002c. 회로에서는 시작 코드가 돌지 않으므로 $ra 값은 회로가 주는 값입니다." 파일에 `reg $ra`가 있으면 그 값도 보인다(넣지는 않는다). 진입 루틴은 entry부터, entry를 담는 `.text` 구간 안에서 entry 뒤의 첫 `jal` 목적지 앞까지(없으면 구간 끝까지)다. 루틴 안의 라벨(`loop`)에서 자르지 않는다. 예외 처리기 없이 어셈블한 이미지에는 이 줄이 없다.
- **상태 표시줄.** 회로의 PC가 entry와 다르면 사실 줄 "PC 0x00400000 · 실행 이미지 진입점 0x00400024"(영어: "PC 0x00400000 · executable image entry 0x00400024"). Messages 진단이 아니다.
- **v2(N-16, D-147).** 화면의 Load Program…은 main 프로세스의 고르기 창(거르개 "Executable image (*.hmx)" 하나)에서 고른 파일을 엔진 `mips.load`로 넣는다. 읽기와 넣을 곳은 트랙 A와 같은 lib-mips 코드(`ProgramLoading` → `ProgramLoader`)가 정하고, 엔진은 되돌리기 한 단계로 넣은 뒤 시뮬레이션을 처음으로 돌린다. 담는 부품이 여럿이면 화면이 묻고 같은 파일로 다시 부른다. PC ≠ entry 사실은 사이클 0에서만 상태 표시줄에 둔다.
- **다시 불러오기(PLAN.md 6.8).** 앱이 도는 동안 엔진이 `.hmx`를 본다: 파일을 연 뒤 처음(저장된 내용과 다르면), 파일이 바뀌면, Reset 앞. 바뀌면 되돌리기 한 단계로 넣고 처음으로 돌린다. 읽지 못하면 올라가 있던 프로그램과 시뮬레이션을 그대로 두고, 화면이 띠 "지금 올라가 있는 것은 마지막으로 불러온 실행 이미지입니다 (시각) · 다시 불러오지 못했습니다: 파일 — 오류"를 보인다(Hallym MIPS의 error-kept 띠).
