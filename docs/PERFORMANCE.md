# 성능 기준

측정은 CI(Linux, GitHub Actions ubuntu-latest)와 개발 PC에서 같은 테스트로 한다. 테스트가 수치를 로그에 남기고(`[perf]` 줄), 기준을 넘으면 실패한다. 중앙값으로 재고 처음 몇 번은 JIT 예열로 버린다.

## Signal Flow(P-07) — `FlowPerformanceTest`

| 항목 | 기준 | 개발 PC(2026-09-26) |
| --- | --- | --- |
| 경로 계산, ref-mips.circ(레지스터·핀·클럭 12곳에서 시작, Through Registers, 가장 느린 곳) | 50 ms 이하 | 5.7 ms(CI 11.5 ms) |
| 경로 계산, demo-datapath.circ(같은 방식, 9곳) | 50 ms 이하 | 1.2 ms(CI 2.5 ms) |
| 프레임 그리기, 연속 흐름, demo-datapath PC 출력(Through Registers, 1600×900 창) | 4 ms 이하 | 1.2 ms |
| 프레임 그리기, 연속 흐름, ref-mips(터널 점프 257개) | 4 ms 이하 | 0.5 ms |
| 프레임 그리기, 앞단이 퍼지는 중(처음 약 2초, 그때그때 그림) | 8 ms 이하 | demo 1.8 ms, ref-mips 0.6 ms |

- CI 기계는 개발 PC보다 약 2.5배 느리다(첫 CI에서 연속 흐름 프레임이 6.1 ms로 기준을 넘었다). 그래서 연속 흐름에서는 멈춘 부분을 그림 한 장으로 만들어 두고 프레임마다 그림 + 대시만 그린다.
- 띠와 대시는 가로·세로 직선이라 사각형으로 채운다. 라벨·칩 글자는 장치 화소 그림으로 한 번 만들어 두고, 호·링을 자르는 영역과 라벨 자리는 경로마다 한 번 계산한다.
- 매 프레임 경로 상자만 다시 그리고, 멈추면 Timer를 세운다(CPU 0에 가깝게). Reduce Motion은 Timer를 돌리지 않는다.

## 기록 엔진(C-01) — `RecordingPerformanceTest`

ref-mips.circ(32레지스터 single-cycle MIPS, 넷 207개)가 끝나지 않는 반복(`tests/record/busy-loop.s`: 메모리 쓰기·읽기, 덧셈, 비교, 분기)을 4000스텝(2000사이클) 도는 동안 잰다.

| 항목 | 기준 | 개발 PC(2026-09-26) |
| --- | --- | --- |
| 캡처 한 번(스텝 하나, 모든 넷) | 1.0 ms 이하 | 0.008 ms(원조 틱+전파 0.36 ms) |
| 지난 스텝 복원, 최근 창(체크포인트에서 63스텝) | 150 ms 이하 | 27 ms |
| 지난 스텝 복원, 오래된 곳(성긴 체크포인트에서 511스텝) | 600 ms 이하 | 215 ms |
| 기본 보관 상한(100,000스텝 = 50,000사이클)까지의 메모리 | 256 MB 이하 | 77 MB |

- 넷 변화는 스텝당 28.6개, 409바이트다(같은 값은 한 객체를 함께 쓴다). 체크포인트 하나(회로 상태 복제, 메모리 내용 포함)는 약 157 KB다.
- 체크포인트: 최근 2048스텝은 64스텝마다, 그보다 오래된 곳은 512스텝마다 하나다. 사용자가 입력을 바꾼 스텝의 체크포인트는 남긴다.
- 보관 상한: 100,000스텝(50,000사이클)이다. 과제 회로는 서브회로 때문에 넷이 ref-mips보다 몇 배 많을 수 있어 256 MB 예산의 약 1/3로 잡았다. 넘으면 오래된 스텝부터 체크포인트 경계에서 버린다.
- 캡처는 원조 엔진의 틱+전파보다 약 40배 빨라 시뮬레이션 속도에 거의 영향이 없다.

## 동적 진단(D-01·D-03)

- 측정: `DynamicCheckTest.scanningAStepIsCheap`. ref-mips + factorial.s를 600스텝 기록한 뒤 101~600스텝을 한 스텝씩 본다(E 발생 출처 추적 + 상태 부품 에지의 X 쓰기 검사).
- 결과: 스텝당 약 0.03 ms(개발 PC). 기록 캡처(0.008 ms)와 원조 틱+전파보다 작다. 시뮬레이터 스레드에서 스텝마다 돌려도 속도에 거의 영향이 없다. 테스트는 2 ms를 넘으면 실패한다.
- 새로 적히거나 버려진 스텝부터만 다시 보므로, 지난 사이클을 볼 때(되돌리기)는 추가 비용이 없다.
